# 对照所提供七项技术的代码结论

| 技术 | 当前系统 | 本轮取舍 |
| --- | --- | --- |
| 动态前瞻 | PredictiveFollower.step已有0.28–0.80m速度/曲率相关追踪目标；race_feedback最终转向由曲率前馈、航向和横向反馈覆盖几何纯跟踪结果 | 不能靠改pursuit_lookahead_scale优化race_feedback。新建可选的转向前馈自适应预瞄，但模型收益不普遍，默认关闭 |
| MPC | 当前是前馈+反馈控制及空间速度包络，名称PredictiveFollower不等于在线MPC | 本轮不替换架构。后续必须先识别执行器/定位响应、验证20ms周期内求解与超时回退，再讨论硬边界约束MPC；不能为了可解随意软化安全约束 |
| ILC | 没有把上一圈误差自动学习成下一圈增速/转向修正 | 暂不基于一圈样本自动加速。空间ILC需位置配准、重复误差置信度、学习滤波与幅度约束，且仍需每周期实时守护。路径/速度交替优化本身不自动构成ILC |
| 赛道记忆 | planned_race.main在发车前build整圈；ClosedPath保存点/曲率；PredictiveFollower初始化速度包络，后续圈按弧长循环查询 | 已具备，不再牺牲首圈录制；新增固定几何/速度查询缓存。每圈不重置起步状态，也不按时间盲放控制指令 |
| 执行器延迟补偿 | 已有steering_preview_time、实测转向反馈补偿、反馈质量衰减；response_delay保留制动响应预留 | 原前馈距离min(2.5*t,v*t)，v>2.5m/s后饱和，是可研究的控制选择而非已证实故障。新增可选曲率适配预瞄；不能仅凭稀疏WARN或电机指令测出舵机延迟 |
| 抓地力在线估计 | 没有经验证的轮胎极限/摩擦系数估计器 | IMU、轮速、定位可用于响应/滑移一致性诊断，但正常低激励数据无法可靠证明峰值摩擦系数。没有实测证据不自动提高横向预算 |
| MPPI | 未使用 | 采样也可能全部无效、权重退化、超时或抖动，不能说“不存在失败”。本轮不引入GPU/采样依赖，先利用现有路线优化空间 |

所贴Monza的3–15m前瞻及论文圈速属于其他平台/赛道，原文未提供也未在本任务核验，不能按比例搬来作为本车的性能或安全证据。直线振荡/切弯也不能单独证明前瞻太小/太大，定位、舵机延迟、反馈增益与多发布者均可能产生相似现象。

P0中的“解除软件限速”不采用。max_speed保持10，全部风险限速/靠墙/偏差/新鲜度检查保留。静止、小幅且受控的转向反馈检查或连续bag拟合可提供响应线索，不能在高速中直接打满转角做辨识。

## 为什么优先路线，而不是继续堆加速度

本次固定官方地图、71秒预算的离线包络：约44.85m一圈、五圈静态包络68.78s、峰值6.35m/s；max_speed=10不约束该模型。以下仅是同路线的模型灵敏度，不是实测可用预算或调参许可：

| 单项模型预算变化 | 五圈静态包络减少 |
| --- | ---: |
| max_speed 10→11 | 0.000s |
| acceleration增加20% | 约0.169s |
| braking增加20% | 约0.493s |
| lateral_accel增加10% | 约2.467s |

不据此提高braking或横向预算。先用不改变运动预算的路线优化改善弯道半径与曲率变化，再看实际跟踪能否兑现。加减速传播包络约占模型时间79.5%，不代表加速度单项就是79.5%的可消除损失。

相同路程从71s到60s需平均速度增加约18.3%，到55s需约29.1%。微秒级查询缓存或起步一小段不可能单独解释全部差距。他队55s只有在同车辆、赛道、圈数及有效判罚条件下才能作为目标参照，不能证明当前任一预算都能安全提高。

## 本轮修改位置

- `track_memory.py::CyclicTrackMemory`：不可变线段投影、循环最小速度与最大曲率查询；非控制指令回放。
- `predictive_follower.py::__init__/start/step/steering_advance`：可选缓存、自适应前馈预瞄；原模式默认保留，起步就绪及硬停车逻辑不变。
- `joint_line_polish.py::polish_line`：静止约束路线优化及原可行性/包络评分门控。
- `planned_race.py::main`：可选路线优化接入，在控制器启动前完成；失败保留原路线。
- `continuous_race.py`：读取新选项，报告实际路线优化记录；受保护的传感器/激光函数不变。
- `planned_race.launch`、`final_speedup.launch/demo`：新增默认关闭的开关；legacy_control强制关闭全部新功能。
- `run_final_speedup.sh`：允许显式传入上述非保护开关；仍禁止越过既有横向/制动预算门槛，不调用start。

没有修改loop_planner.py的feasible、segment_check和墙距停车，也没有修改reference_clearance、车辆模型、地图、PID、裁判或官方校验。完整差异见 `CHANGES.patch`。
